# 018. One Composition Root Builds All Services
Status: Accepted | Date: 2026-10-16 | Amends: ADR-012

## Context
ADR-012 made REST and MCP thin adapters over shared services, but each adapter still assembled those services itself: FastAPI's `core/dependencies.py`, MCP's `tools.py`, `resources.py` and `auth.py`, plus the eval runner. The copies drifted (MCP resources built `WorkspaceService` without its cache wrapper), MCP imported repositories behind import-linter exceptions, and adapters reached into `_private` service methods. `DocumentService.create` also took FastAPI's `UploadFile`, so business logic depended on the web framework.

## Decision
`src/composition.py` is the only module in `src` that imports repository implementations; import-linter forbids `src.repositories` everywhere else, except the Protocols services depend on. `Services(session, redis, http_client)` builds each service lazily (`cached_property`), so one instance is one unit of work: every service in it shares the session and a single embedding client. It never opens resources itself; the caller owns their lifetime. FastAPI's `get_services` takes them from `Depends` (cached per request), `open_services()` opens one session per call for MCP, and Celery tasks (Track 3) will pass their own engine and clients, as CLAUDE.md requires. Known exception until Track 3: research's background task keeps using the request's session after it closes. The module sits at the top level, not in `core/`: services import `core`, so a root inside `core` would create an import cycle. Services expose public, `workspace_id`-scoped methods; membership is checked once at the adapter boundary. Uploads enter as a domain `DocumentUpload` (filename, content type, declared size, sync binary stream).

## Consequences
A wiring change, such as a new cache, applies to every entry point at once, and a unit test pins the cached repositories. The cost is one indirection, and `Services` grows with each new service. **Rejected: a DI framework** (dependency-injector, dishka): automatic wiring and a new dependency are hard to justify for seven explicitly constructed services. **Rejected: free builder functions** (`build_search_service(session, http)`): every caller must know each builder's resources, and two builders in one request each build their own embedding client. **Rejected: passing a `Workspace` ORM object as proof of membership**: anything can load one, and the private `workspace_id` twins showed that callers holding only an ID went around it.
