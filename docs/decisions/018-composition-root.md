# 018. One Composition Root Builds All Services
Status: Accepted, amended by ADR-033 (a unit-of-work factory instead of a session; one `Services` per process, built in the lifespan) | Date: 2026-10-16 | Amends: ADR-012

## Context
ADR-012 made REST and MCP thin adapters over shared services, but each adapter still assembled those services itself: FastAPI's `core/dependencies.py`, MCP's `tools.py`, `resources.py` and `auth.py`, plus the eval runner. The copies drifted (MCP resources built `WorkspaceService` without its cache wrapper), MCP imported repositories behind import-linter exceptions, and adapters reached into `_private` service methods. `DocumentService.create` also took FastAPI's `UploadFile`, so business logic depended on the web framework.

## Decision
`src/composition.py` is the only module in `src` that imports repository implementations; import-linter forbids `src.repositories` everywhere else, except the Protocols services depend on. `Services(uow, redis, http_client)` builds each service lazily (`cached_property`) on a unit-of-work factory, with a single embedding client. It holds no session (each service method opens its own unit of work, ADR-033), so the API builds one per process. It never opens resources itself; the caller owns their lifetime: the API's lifespan opens the engine and clients, builds `Services` and hands it to every request as lifespan state, where REST's `get_services` and MCP's `get_mcp_services` read it. A Track 3 research worker will build its own from its own engine and clients, as CLAUDE.md requires (the pipeline workers need no `Services`: ADR-027). The module sits at the top level, not in `core/`: services import `core`, so a root inside `core` would create an import cycle. Services expose public, `workspace_id`-scoped methods; membership is checked once at the adapter boundary. Uploads enter as a domain `DocumentUpload` (filename, content type, declared size, sync binary stream).

## Consequences
A wiring change applies to every entry point at once; unit tests pin the wiring, and `tests/integration/test_lifespan.py` that the lifespan's one instance serves both REST and MCP. The cost is one indirection, and `Services` grows with each new service. **Rejected: a DI framework** (dependency-injector, dishka): automatic wiring and a new dependency are hard to justify for seven explicitly constructed services. **Rejected: free builder functions** (`build_search_service(session, http)`): every caller must know each builder's resources, and two builders in one request each build their own embedding client. **Rejected: passing a `Workspace` ORM object as proof of membership**: anything can load one, and the private `workspace_id` twins showed that callers holding only an ID went around it.
